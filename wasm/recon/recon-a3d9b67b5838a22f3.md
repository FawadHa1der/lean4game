- **Flagship games** hard-coded in `relay/src/index.ts:113-122` (`/api/games` endpoint): leanprover-community/nng4, hhu-adam/robo, alexkontorovich/realanalysisgame, djvelleman/stg4, trequetrum/lean4game-logic, emilyriehl/reintroductiontoproofs, jadabouhawili/knightsandknaves-lean4game, zrtmrh/linearalgebragame. Landing page fetches `/api/games` and renders tiles (`client/src/components/landing_page.tsx`), each tile from `game.json`'s `tile` field (`GameTile` in `client/src/store/api.ts:8-17`: title/short/long/languages/prerequisites/worlds/levels/image).
- **Import flow** (`doc/publish_game.md`, `relay/src/import.ts`): game repo's GitHub Action uploads a zip artifact; hitting `adam.math.hhu.de/import/trigger/{USER}/{REPO}` (routes at index.ts:26-27) triggers `doImport` — Octokit picks the *latest* actions artifact, downloads the zip, `relay/scripts/unpack.sh` unzips into `games/{owner}/{repo}` (double-unzip: artifact zip contains one inner zip), `relay/scripts/install_toolchain.sh` runs `elan toolchain install $(head lean-toolchain)`. Status page polls `/import/status/{owner}/{repo}`. No config.yml exists; the featured list is a TODO-noted hard-coded array.
- **Artifact set a production game ships** (what unpack must yield, per serverProcess.ts + index.ts + SaveData.lean):
  - `lean-toolchain` (for elan install),
  - full lake build tree so `lake serve` works: `.lake/build/...` incl. compiled game oleans and the `GameServer` dependency package,
  - `.lake/gamedata/` — the static JSON baked by `MakeGame` (`server/GameServer/SaveData.lean:28-33`): `game.json`, `inventory.json`, `level__{world}__{level}.json`, `doc__{Theorem|Tactic|Definition}__{name}.json`, plus `images/` copied into `.lake/gamedata/images` (SaveData.lean:12-25),
  - `.i18n/{lang}/Game.json` translation files,
  - `Game/Metadata.lean` on disk (relay rewrites every URI to `file://{gameDir}/Game/Metadata.lean`, serverProcess.ts:221,244),
  - optionally (legacy ≤v4.7.0) `.lake/packages/GameServer/server/.lake/build/bin/gameserver` — detected in `getCustomLeanServer` (serverProcess.ts:73-81), which switches the relay to pass-through mode.
- **Runtime protocol** (the thing the wasm worker must reproduce; `relay/src/serverProcess.ts:140-299` `messageTranslation`): client connects to `ws(s)://host/websocket/g/{owner}/{repo}` (URL built in `client/src/store/editor-atoms.ts:15`; relay regex `/^\/websocket\/g\/([\w.-]+)\/([\w.-]+)$/` serverProcess.ts:39). Relay spawns `lake serve --` in the game dir and rewrites LSP traffic: on `initialize` it captures `initializationOptions.difficulty` and `.inventory` and abuses `rootUri` to carry the game name; on `textDocument/didOpen` of client-side URI `file:///{worldId}/{levelId}.lean` it wraps the user text as `import {levelData.module} import GameServer.Runner \nRunner "{game}" "{world}" {level} (difficulty := d) (inventory := [...]) := by\n{content}\n`, reading `level__{world}__{level}.json` for `module`; all lines are shifted by `PROOF_START_LINE = 2` client→server and −2 server→client; server→client URIs rewritten back to `file:///{worldId}/{levelId}.lean`; semanticTokens/range disabled and full-token arrays re-based (serverProcess.ts:272-295). Game-specific RPC: `Game.getProofState` and `Game.getInteractiveGoals`, `@[server_rpc_method]` in `server/GameServer/RpcHandlers.lean:359-364`, called from `client/src/components/infoview/info.tsx:317,323` and `goals.tsx:372`; response types in `client/src/components/infoview/rpc_api.ts` (`ProofState{steps, diagnostics, completed, completedWithWarnings}`, `GameHint{text, hidden, rawText, varNames}`). `server/GameServer/Runner.lean` also enforces locked/disabled tactics/theorems by difficulty (`findForbiddenTactics`).
- **Static data endpoints served by relay** (`relay/src/index.ts`): `GET /data/g/{owner}/{repo}/{file}` → `.lake/gamedata/{file}` (empty `{}` JSON fallback on miss); `GET /i18n/g/{owner}/{repo}/{lang}` → `.i18n/{lang}/Game.json` (with access logging; `{}` fallback); `GET /api/games`; `GET /data/stats`; `GET /api/game-sessions` on separate API_PORT (websocket.ts `GameSessionsObserver.getAllConnectedPlayers`). Client fetches: `/data/{gameId}/game.json` and `level__{world}__{level}.json` (`client/src/store/query-atoms.ts:13,34`), `inventory.json` and `doc__{Type}__{name}.json` (+ legacy `doc__Lemma__` fallback) (`client/src/store/inventory-atoms.ts:21,34,49`).
- Process pre-warming queues per popular game in `GameManager.queueLength` (serverProcess.ts:31-36) — irrelevant for wasm (each tab is its own server) but explains adam's UX latency bar.

- **Game i18n** (lean-i18n): game repo ships `.i18n/{lang}/Game.po` + exported `Game.json`; keys are source strings with code/latex blocks replaced by `§n` placeholders. Client mirror of that transformation: `client/src/utils/translation.ts` — `extractCodeBlocks` regex ``/((?<!\\)(`+|\${1,2})([\s\S]*?)\2)/g``, `useGameTranslation()` wraps `t` with ns = gameId (`g/owner/repo`), restores `§n` → original blocks. - **Game images**: game's `images/` folder → copied to `.lake/gamedata/images/` at MakeGame (SaveData.lean:12-25) → served under `/data/g/{owner}/{repo}/images/...`; markdown `![x](images/y.png)` auto-prefixed with `data/{gameId}/` (`client/src/components/markdown.tsx:19`); world intro image via `Image "images/..."` command shows in `world-image-container` (level.tsx:601-616, main.tsx:571-573). ### Notes for the wasm-port architecture decision
- The seam to cut is exactly `messageTranslation` (`relay/src/serverProcess.ts:140-299`) + the four static routes (`/data/...`, `/i18n/...`, `/api/games`, websocket). Everything client-side speaks (a) plain fetches of baked JSON and (b) LSP-over-websocket via lean4monaco (`store/editor-atoms.ts:11-24` is the single place the websocket URL is constructed; `level.tsx:40-64` shows the client can be re-pointed by swapping `setupMonacoClient`). Reimplementing the didOpen-wrapping/line-shifting in a browser shim in front of the QED64 worker, plus serving `.lake/gamedata` + `.i18n` as static files, should leave the entire cypress suite valid as-is except `baseUrl` and the relay-specific `/data/stats` bits.
- `MakeGame` on the wasm toolchain must still emit `.lake/gamedata` (SaveData.lean is pure IO writes) — that can be baked at pack-build time on the host; only `GameServer.Runner` + `RpcHandlers` must run inside the wasm Lean server.
- Difficulty/inventory enforcement lives server-side (Runner.lean `findForbiddenTactics`), so the wasm server needs the game's `gamedata` visible on its virtual FS (it reads `loadLevelData "."` relative to the game dir).
